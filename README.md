# Konstantin Ivanov — CV site

Одностраничник-резюме. Тот же макет и та же палитра, что и у версии без
сборки, но собранный из компонентов: **Next.js (App Router) + TypeScript +
Tailwind CSS v4 + shadcn/ui**. На выходе — по-прежнему статика: `next build`
кладёт готовый HTML в `out/`, и его можно положить на любой хостинг, где нет
никакого Node.

## Идея макета

Страница собрана не как лендинг, а как бланк. Вся она стоит на одной сетке —
«поля документа + текст»: слева всегда метаданные, справа всегда содержание.

Из этого следует остальное:

- **Заголовка над разделом нет.** Название раздела живёт на полях и несёт
  фактическую приписку: `history / 5 roles`, `stack / 7 areas`,
  `contact / utc+3`. В отличие от прежней версии приписки не проставляются
  руками, а считаются из данных — соврать молча они больше не могут.
- **Квадратный маркер** слева от названия раздела краснеет, пока раздел
  читают. Это единственное состояние, которое считает клиентский код, и оно же
  подсвечивает пункт меню в шапке — одно состояние, показанное дважды.
- **Засечный шрифт появляется ровно один раз** — на имени, и это единственный
  текст крупнее 18px. Вся смелость макета потрачена там, поэтому всё остальное
  держится тихо. Если захочется добавить второй крупный акцент — сначала
  уберите первый.

## Что изменилось против версии без сборки

| Было | Стало | Зачем |
|---|---|---|
| 21 CSS-файл, порядок `<link>` = каскад | Tailwind v4, токены в `globals.css` | порядок больше не хрупкий: сломать каскад перестановкой строк нельзя |
| текст резюме внутри `index.html` | `src/content/cv.ts` | правится один файл; разметка текста не знает |
| `5 roles`, `7 areas` руками | считаются из массивов | приписка не может разойтись с содержимым |
| свой CSS на кнопку, бейдж, таблицу, аватар | shadcn/ui | доступность, фокус и клавиатура — из коробки |
| `onerror` на `<img>` для фолбэка фото | `Avatar` / `AvatarFallback` | состояние загрузки внутри компонента |
| скрипт темы в `<head>` + `localStorage` руками | `next-themes` | плюс третий режим — «следовать за системой», к которому можно вернуться |
| `<link>` на Google Fonts | `next/font` | шрифты со своего домена, без стороннего запроса и сдвига макета |
| `robots.txt` и Schema.org правились вручную | `robots.ts`, `sitemap.ts`, `lib/json-ld.ts` | домен и данные подставляются из одного места |
| `components.html` отдельным файлом | маршрут `/components` | справочник импортирует те же компоненты, что и резюме |

Что **не** изменилось: палитра (все hex перенесены как есть, они проверены по
контрасту), метрика, обе темы, поведение печати и то, что страница читается
целиком без JavaScript.

## Компоненты

Примитивы — из [shadcn/ui](https://ui.shadcn.com): они лежат в репозитории как
обычный код, поэтому их можно читать и править, а не догадываться о поведении
зависимости. Живые примеры каждого — на `/components`.

| Компонент | Откуда | Где на странице |
|---|---|---|
| `Button` | shadcn/ui | действия (`ActionButton` задаёт метрику бланка) |
| `Badge` | shadcn/ui | статусы и элементы стека |
| `Card` | shadcn/ui | запись о работе |
| `Table` | shadcn/ui | стек: область → инструменты |
| `Avatar` | shadcn/ui | фото, фолбэк на инициалы |
| `DropdownMenu` | shadcn/ui | выбор темы |
| `Separator`, `Tooltip` | shadcn/ui | справочник, резерв |
| `TextLink` | свой | ссылки, стрелка у внешних |
| `DataList` | свой | реквизиты, языки, контакты |
| `LedgerSection` | свой | сетка «поля + текст» |
| `SectionHeading` | свой | ключ раздела на полях |

Оформление примитивов снято до бланка не переопределением цветов в компонентах,
а тем, что палитра разложена по именам токенов shadcn: `--background` — это
бумага, `--primary` — оксблад, `--muted-foreground` — служебный серый. Хардкод
цвета в компоненте — это баг: он не переключится вместе с темой.

## Что нужно заполнить

1. `public/img/photo.png` — фото. Если файла нет, `Avatar` покажет инициалы
   «KI», страница не сломается.
2. `public/docs/Konstantin_Ivanov_CV.pdf` — PDF для кнопки «Download CV».
3. `src/content/cv.ts` → `profile.telegram` и `profile.github`: подставить ник
   и профиль. Если публичных репозиториев нет — удалить строку GitHub из
   массива `contacts`, часовой пояс там уже есть.
4. `src/lib/site.ts` → `siteUrl`: заменить `https://example.com` на реальный
   домен. Отсюда он разойдётся в og-теги, `robots.txt` и `sitemap.xml`.
5. `profile.revision` — дата ревизии документа. Обновлять при правках; полоса
   реквизитов и приписка на полях берут её оттуда.

## Темы

Светлая — по умолчанию, тёмная — полноценная вторая тема, не инверсия: бумага
становится графитом, оксблад светлеет до терракоты, иначе он не проходит по
контрасту на тёмном.

- Первый заход: берётся системная настройка.
- Меню в шапке даёт три варианта: Light, Dark, System. Выбор запоминается и с
  этого момента побеждает системную настройку — но вернуться к ней можно, в
  прежней версии это была дорога в один конец.
- `next-themes` сам вставляет синхронный скрипт до первой отрисовки, поэтому
  моргающего кадра нет.

Вся палитра обеих тем лежит в `src/app/globals.css` и больше нигде.

Зелёный (`--pass`) зарезервирован под одну семантику — «доступен, проверено,
пройдено» — и больше нигде не используется. Акцент (`--primary`) — ссылки,
фокус, активный раздел, метка «current». Если понадобится третий цвет, скорее
всего он не нужен.

## Доступность

- Все цвета текста проходят WCAG AA в обеих темах, включая самые мелкие
  mono-подписи (минимум 4.9:1).
- Один видимый стиль фокуса на всю страницу, задан в `globals.css`.
- Ничего не появляется по скроллу: с выключенным JavaScript страница читается
  целиком, прятать контент под `opacity: 0` не нужно.
- `prefers-reduced-motion` выключает и без того немногочисленные переходы.
- Стек — настоящая `<table>` с `<th scope="row">`, а не сетка из `<div>`.
- Меню темы, фокус-ловушка и роли ARIA достаются от Radix через shadcn/ui.

## Печать

Рекрутеры действительно сохраняют такие страницы в PDF. Всё, что относится к
одному компоненту, сказано рядом с ним вариантом `print:` (`print:hidden` на
шапке и кнопках, `print:break-inside-avoid` на записи о работе). В
`globals.css` осталось только то, что относится к документу целиком:
переопределение токенов на чёрно-белые, кегль и раскрытие адресов ссылок.

## Локальный запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # статика в out/
npx serve out      # посмотреть, что получилось
```

Добавить новый компонент shadcn:

```bash
npx shadcn@latest add <name>
```

## Деплой

`npm run build` даёт папку `out/` — дальше любой статический хостинг:
Netlify, Cloudflare Pages, Vercel. Build command `npm run build`, publish
directory `out`.

### GitHub Pages

Уже настроено: `.github/workflows/deploy.yml` собирает и публикует сайт на
каждый push в `main`.

1. В репозитории: **Settings → Pages → Source → GitHub Actions**.
2. Проверить тип страницы:
   - репозиторий называется `<username>.github.io` → сайт на корне,
     `NEXT_PUBLIC_BASE_PATH` не нужен, workflow сам оставит его пустым;
   - любое другое имя репозитория (Project Pages) → сайт будет на
     `https://<username>.github.io/<repo>/`, workflow сам подставит
     `NEXT_PUBLIC_BASE_PATH=/<repo>` на сборке — ничего вручную делать не
     надо.
3. `src/lib/site.ts` → `siteUrl`: указать финальный адрес (тот же, что и в
   пункте 2) — иначе og-теги, `robots.txt` и `sitemap.xml` будут ссылаться на
   `example.com`.
4. Push в `main` — во вкладке **Actions** будет видно прогресс.

Не через Actions, а вручную — собрать с нужным basePath и запушить `out/` в
ветку `gh-pages`:

```bash
NEXT_PUBLIC_BASE_PATH=/<repo> npm run build
touch out/.nojekyll
npx gh-pages -d out
```

`basePath` — это подпуть на Project Pages; на User/Org Pages
(`<username>.github.io`) переменную не задавать. `.nojekyll` обязателен: без
него GitHub Pages прогоняет Jekyll, который по умолчанию игнорирует папки с
подчёркиванием, а Next.js кладёт чанки в `_next/` — без этого файла сайт
соберётся без единого стиля.
